## v1.18.4 GUI 重大修复（SyncthingIgnoreGUI.ps1）
审查发现 Scan/Apply **两个核心功能完全不可用**，根因链（均已实测确认并修复）：

1. **runspace 隔离（致命）**：`[powershell]::Create()` 新建独立 runspace，既看不到脚本作用域函数（`AddCommand('Invoke-ScanCore'/'Start-ApplyJob')` 抛 `CommandNotFoundException`），也看不到脚本变量。修复：`New-BackgroundRunspace` 用 `InitialSessionState::CreateDefault()` + `SessionStateFunctionEntry` 复制所需函数，再把作业所需变量经「包装 scriptblock 赋值局部变量」注入（`AddScript` + `AddArgument`）。
   - 关键坑 A：`InitialSessionState::Create()` 是**空 ISS，无 FileSystem 提供程序**，后台 `Get-Content -Raw` 读文件返回空 → 必须用 `CreateDefault()`。
   - 关键坑 B：`[InitialSessionState]::CreateFromSessionState()` 此环境**不存在**，勿用。
   - 关键坑 C：`SessionStateVariableEntry` 复制的变量**不会绑定到复制函数的局部作用域**，必须用包装 scriptblock 注入。
   - 关键坑 D：`[powershell]::Create()` **无接收 Runspace 的重载**，只能传 `InitialSessionState`；释放 runspace 用 `$ps.Runspace.Dispose()`。
2. **Control.Invoke 闭包失效**：PowerShell 闭包经 `$form.Invoke([Action]{...})` 执行时**无法捕获脚本变量**（实测闭包内改 `$form.Tag`/控件均不生效）。Apply 的进度/状态/摘要/日志全部改走 `Synchronized` 共享状态（`New-ApplyState`/`Add-ApplyLog`）+ UI Timer 轮询（与 Scan 一致）。`Write-LogLine` 回退为仅 UI 线程直接写。
3. **中文 `-f` 运算符优先级 bug（既有）**：`(Decode-Uni $X -f $a)` 被解析为把 `-f` 当作 `Decode-Uni` 的参数而非格式化运算符，导致中文状态/摘要/进度/确认框/关于框显示**未替换的模板字面量**（如 `已找到 {0}`）。修复为 `((Decode-Uni $X) -f $a)`，共 12 处（$tpl/$scanTpl/$applyTpl/$T[$lang].summary/applyConfirm/aboutText/manifestLoaded）。
4. 次要：`Write-LogLine` 的 `$Color` 参数此前被忽略（改用 `RichTextBox` 逐行着色）；`cmbLang` 项本地化（中文界面显示 英文/中文）；`Pick-File` 初始目录跟随清单路径。

验证方式：AST 抽取脚本真实函数定义 + 后台 runspace 端到端跑 `Invoke-ScanCore`/`Start-ApplyJob`（临时目录含 `.git`），确认扫描读到文件、应用 `Progress=100`、摘要 `已找到 1`、中文日志渲染正确。版本同步至 v1.18.4（脚本头/$ScriptVersion/.stignore 头/README 徽章/openspec/CHANGELOG）。

### 补充审计（同版本内）
- 实测 `CreateDefault` runspace 具备 FileSystem 提供程序与全部 6 个驱动器（C/D/E/F/G/Z），故 `Invoke-ScanCore` 在 `Root` 为空时走 `Get-PSDrive -PSProvider FileSystem` 的「扫描全部盘」路径可用；`Test-Path`/`Get-FileHash`/`Get-Content`/`Copy-Item`/`Set-Content` 均正常。
- 逐个审计后台作业调用链：`Start-ApplyJob` 仅依赖已复制函数（`Lmsg`/`Decode-Uni`/`Shorten-Path`/`Limit-Backups`/`Add-ApplyLog`）+ 内置 cmdlet + `[System.IO.*]`，自包含无遗漏；`Start-ParallelScan` 用 `[System.IO.DirectoryInfo]` 而非 `Get-ChildItem`，对提供程序无依赖。
- Apply Timer 取消分支在 `IsCompleted` 判断**之前**提前 return，故取消不会触发 `EndInvoke` 的 `PipelineStoppedException`、不会误报 Red ERROR —— 原审查中怀疑的该问题实际不存在，未改动。
- 修正既有中文串笔误：停止应用提示中 `\uff1c`（全角小于号 ＜）误用，应为 `\uff1b`（；）。
- 确认全部 `Add-Log`/`Write-LogLine` 调用点均位于 UI 线程（按钮/计时器回调），无后台跨线程控件访问。
