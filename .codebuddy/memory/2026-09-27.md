## 修复 CI 阻断型检查：根/.stignore 与 app/assets/.stignore 不一致
- CI `validate` 报错：副本 `app/assets/.stignore` 比根 `.stignore` 多一行 `**/.venv/`（root-only=[]，copy-only=[**/.venv/]）。
- 历史取证（git log -S pickaxe）：副本的 `**/.venv/` 自 `470d344`（Flutter 重写）起长期存在；根在 `2de26c1`（Sep25 22:47，chore: 同步 Flutter 主实现至 v1.26.1）diff 中 `-**/.venv/` 被删除，副本未同步 → 版本同步提交的副作用导致根丢行。
- 决策：把 `**/.venv/` 补回根 `.stignore`（位于 `**/.pub-cache/` 与 `**/.venv-*/` 之间，第 140 行），使根=副本并保留该长期有用规则；而非删除副本那行。
- 验证：用 CI 同款逻辑（`Get-Content -Encoding utf8` 读 + CRLF→LF 归一化后 `-eq`）确认 "Ruleset copies are identical"，exit 0。
- 工作树：仅 `.stignore` 被修改（待用户本地提交）。未改 `//Version:1.18.5` 头——CI 只校验两文件逐行一致，不校验版本头。
- 经验：CI 阻断规则集一致性时，先用 `git log -S` 判"补根/删副本"方向；本次根是在 sync 提交中被意外删行，故补回根。PowerShell `Get-Content` 须带显式 `-Encoding` 否则被安全启发式拦截。
